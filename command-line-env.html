Command-line Environment

How command-line programs talk to each other and to the shell — arguments, streams, environment variables, exit codes and signals — plus SSH, tmux and making the shell your own.

Big idea. The shell is a programming language built around running programs and wiring them together. That only works because CLI programs follow shared conventions. Learn the conventions and every new tool feels familiar.

01The CLI contract

A Python function shows its inputs and outputs in its signature. A shell program doesn't — it talks through five kinds of channel: arguments, streams (in, out, err), environment variables, return codes and signals. Click each one.

📥 Arguments $1 $@
🌿 Environment variables $HOME
⌨️ Standard input stdin
your program/usr/bin/whatever
📤 Standard output stdout
⚠️ Standard error stderr
🔢 Return code $?
⚡ Signals Ctrl-C
Click a channel to see what it does.

Decoding the lecture's example script

save-errors.sh
#!/usr/bin/env bash
if [[ -f $1 ]]; then              # argument: target file name
    echo "Target file already exists"
    exit 1                       # return code: failure
else
    if $DEBUG; then              # environment variable
        grep 'error' - | tee $1  # "-" = read stdin; tee also shows output
    else
        grep 'error' - > $1      # redirect stdout into the file
    fi
    exit 0                       # return code: success
fi

02Arguments, flags & globs

Every argument is just a string. ls -l folder/ runs /bin/ls with the list ['-l', 'folder/'] — the program decides what they mean.

$0

Name of the script / program

$1 … $9

First to ninth argument

$@ · $#

All arguments · how many there are

Flag conventions

ConventionExample
Short flags: one dash, one letterls -a
Long flags: two dashes, a wordls --all (same as -a)
Short flags can be groupedls -l -a = ls -la
Order usually doesn't matterls -la = ls -al
Near-universal flags--help · --verbose · --version
-- ends flag parsingrm -- -myfile treats -myfile as a name
Many args = same action on eachmkdir src docs

Dashes are a convention, not a rule of the shell — libraries like Python's argparse follow it so tools behave predictably.

Globs: the shell expands patterns before the program runs

Typing rm *.py never passes *.py to rm. The shell finds matching files and passes their names instead — e.g. ['main.py', 'utils.py']. That's why rm *.py replaces a whole loop.

*

Zero or more of any character

?

Exactly one character

{a,b,c}

Expands to each comma-separated item (even for files that don't exist yet)

🧪 What does the program actually receive?
program flag from a glob glob with no match (passed literally)
You typeProgram receives
rm *.pymain.py test_main.py utils.py
touch folder/{a,b,c}.pyfolder/a.py folder/b.py folder/c.py
cp {setup,build,deploy}.sh /newpathsetup.sh build.sh deploy.sh /newpath
mv *{.py,.sh} folderevery .py file, every .sh file, folder
echo '*.py'*.py — quotes stop expansion
🔁
zsh also supports ** for recursive matches: rm **/*.py deletes .py files in every subfolder.

03Streams

Every program has one input stream (stdin) and two output streams (stdout, stderr).

⚡
Pipelines run concurrently. In cat myfile | grep -P '\d+' | uniq -c, the shell starts all three programs at once and connects them; data flows through as it's produced. You can prove it: put sleep 15 && cat … at the front and ps shows grep, sort and uniq already running.
stdin

Input. Connected automatically when piping. Many tools accept - as a filename meaning “read stdin”.

stdout

Normal output — the stream that flows into the next command in a pipe.

stderr

Warnings and errors. Not piped, so they reach you even mid-pipeline.

🚦 Stream router — where does each stream go?
$ ls /tmp /nonexistent
■ stdout   ■ stderr

Redirection reference

SyntaxEffect
cmd > fstdout → file (overwrite)
cmd >> fstdout → file (append)
cmd 2> fstderr → file
cmd &> fboth stdout and stderr → file
cmd < fstdin ← file
cmd > /dev/null 2>&1discard everything
🔍
fzf — a fuzzy finder in true Unix style: it reads lines on stdin and lets you filter and pick interactively. Try ls | fzf or cat ~/.bash_history | fzf.

04Variables & the environment

Assign with foo=bar, read with $foo. All shell variables are strings.

Works

foo=bar

Breaks

foo = bar runs a program called foo with arguments = and bar. Spaces split arguments!

Quotes are not interchangeable

bash
$ foo=bar
$ echo "$foo"      # double quotes expand variables
bar
$ echo '$foo'      # single quotes are literal
$foo

Capturing output

Command substitution $( )

files=$(ls) stores ls's stdout (newlines included) in a variable you can reuse: echo "$files" | grep README.

Process substitution <( )

Runs a command and hands over its output as a temporary file name — for tools that want files, not stdin: diff <(ls src) <(ls docs).

Environment variables: who can see what?

When the shell starts a program, it passes along its environment. printenv lists it. Conventionally these are ALL_CAPS (HOME, PATH, TZ) and let you change a program's behaviour without flags.

How you set itCurrent shell sees itChild programs see it
DEBUG=1✅❌
TZ=Asia/Tokyo date (prefix)❌✅ that one command only
export DEBUG=1✅✅ all from now on
unset DEBUGremoves it
bash
$ TZ=Asia/Tokyo date     # current time in Tokyo
$ echo $TZ               # empty: only the child got TZ
$ export DEBUG=1
$ bash -c 'echo $DEBUG'   # child shell inherits it
1

05Return codes

Every program ends with a number: 0 = success, anything else = something went wrong. $? holds the last one; exit N sets it in a script.

&& and || work on these codes and short-circuit — so they double as compact conditionals. if and while use exit codes too.

🔀 && / || simulator
echo "ran!"
bash
grep -q "pattern" file.txt && echo "Pattern found"
grep -q "pattern" file.txt || echo "Pattern not found"
true  && echo "always prints"    # true always succeeds
false || echo "always prints"    # false always fails

if grep -q "pattern" file.txt; then echo "Found"; fi
while read line; do echo "$line"; done < file.txt

06Signals & job control

Signals are software interrupts: the process pauses, handles the signal, and may change course. Pressing Ctrl+C makes the shell send SIGINT — which a program is free to catch and ignore.

SignalSent byMeaningCatchable?
SIGINTCtrl+CInterruptYes
SIGQUITCtrl+\Quit (stronger)Yes
SIGTERMkill -TERM <PID>Please exit gracefullyYes
SIGTSTPCtrl+ZPause (terminal stop)Yes
SIGHUPclosing the terminalHang upYes
SIGKILLkill -9 <PID>Die now — may leave orphaned childrenNo

The lecture's Python demo catches SIGINT and keeps running; only SIGQUIT (Ctrl+\) stops it. See all signals with man signal or kill -l.

Job control toolkit

cmd &

Start in the background (still prints to your terminal — redirect if noisy).

fg / bg

Resume a paused job in the foreground / background. Ctrl+Z then bg backgrounds a running program.

jobs

List this terminal's unfinished jobs. Refer to them as %1, %2…; $! = last background job.

nohup / disown

Survive closing the terminal (ignore SIGHUP) — at launch, or for a job already running.

pgrep / pkill

Find / signal processes by name instead of PID.

trap

Run cleanup code in a script on exit or on a signal.

Step through a session

Cleanup with trap

cleanup.sh
#!/usr/bin/env bash
cleanup() {
    echo "Cleaning up temporary files..."
    rm -f /tmp/mytemp.*
}
trap cleanup EXIT              # run when the script exits
trap cleanup SIGINT SIGTERM    # and on Ctrl-C or kill

07Remote machines (SSH)

ssh alice@server.mit.edu gives you a shell on another computer. It can also run a single command and stream its input/output back.

💻 Your laptop
⇄
🖥 server
CommandOn the serverOn your laptop

ssh alice@server 'ls | wc -l'ls | wc -ljust shows the result

SSH keys (prefer them to passwords)

Public-key cryptography proves you hold a private key without ever sending it. Your private key (~/.ssh/id_ed25519) is effectively your password — never share it.

bash
# generate a key pair
ssh-keygen -a 100 -t ed25519 -f ~/.ssh/id_ed25519

# check / validate the passphrase
ssh-keygen -y -f ~/.ssh/id_ed25519

# install your public key on the server (goes into ~/.ssh/authorized_keys)
ssh-copy-id -i ~/.ssh/id_ed25519 alice@remote

Copying files

scp

The classic: scp local_file host:path/remote_file

rsync

Skips files already identical on both sides, handles permissions/symlinks, and --partial resumes interrupted copies.

~/.ssh/config — nicknames & defaults

~/.ssh/config
Host vm
    User alice
    HostName 172.16.174.141
    Port 2222
    IdentityFile ~/.ssh/id_ed25519

# wildcards work too
Host *.mit.edu
    User alice

Now ssh vm just works — and so do scp, rsync and mosh, which read the same file.

📶
mosh is an SSH alternative that survives sleep, network changes and laggy links.

08Terminal multiplexers: tmux

Many shells in one terminal — and sessions that keep running after you detach, perfect on remote servers (no nohup tricks needed).

Every shortcut starts with the prefix Ctrl+b: press it, release, then press the key. Written <C-b> x.

Sessions

Independent workspaces.
tmux · tmux new -s NAME · tmux ls · tmux a (-t to pick) · <C-b> d detach

Windows

Like browser tabs.
<C-b> c new · <C-b> N go to N · p/n prev/next · , rename · w list

Panes

Splits in one view.
<C-b> " split top/bottom · % side-by-side · arrows move · z zoom · [ scrollback · space cycle layouts

09Customizing the shell

Most CLI tools are configured with plain-text dotfiles — names starting with . so ls hides them by default.

ToolConfig file(s)
bash~/.bashrc, ~/.bash_profile
git~/.gitconfig
vim~/.vimrc, ~/.vim/
ssh~/.ssh/config
tmux~/.tmux.conf

Extending $PATH

~/.bashrc
export PATH="$PATH:path/to/append"   # keep the old value, add a folder

Installing tools

Package managers

macOS Homebrew · Ubuntu/Debian apt · Fedora dnf · Arch pacman. e.g. brew install ripgrep fd

command-not-found.com

Look up how to install any missing command on any distro.

tldr

Example-first mini man pages: tldr fd.

🛑
Careful with curl … | bash. It runs a script you haven't read. Safer: download it (curl -fsSL URL -o install.sh), read it (less install.sh), then run it.

Aliases

~/.bashrc
alias ll="ls -lh"          # no spaces around = !
alias gs="git status"
alias sl=ls                 # typo insurance
alias mv="mv -i"            # ask before overwriting
alias mkdir="mkdir -p"      # create parent dirs
alias la="ls -A"; alias lla="la -l"   # aliases compose

\ls          # bypass an alias once
unalias la   # remove it
alias ll     # show its definition

Aliases can't take arguments in the middle — use a shell function for that. And press Ctrl+R to search your history (with fzf installed, it becomes fuzzy search).

Managing dotfiles

Keep them in one folder, under version control (git), and symlink them into place with a script.

⚡ Easy installs

New machine set up in a minute.

🧳 Portability

Tools behave the same everywhere.

🔄 Sync

Edit anywhere, keep every machine in step.

🕓 History

Version history for a config you'll keep for years.

Learn from others' dotfiles on GitHub (the instructors publish theirs) — but don't copy blindly.

10AI in the shell & terminal emulators

Generate

Commands from English

llm cmd "find all python files modified in the last week" → find . -name "*.py" -mtime -7

Pipe

LLMs in pipelines

Great for messy text where regex hurts: llm "$INSTRUCTIONS" < users.txt pulls usernames out of inconsistent lines. Quote the variable — it has spaces.

Agent

AI shells

Tools like Claude Code take English instructions and turn them into shell commands, file edits and multi-step tasks.

Pick a terminal emulator worth living in

You'll spend hundreds of hours there, so tune: font · colour scheme · keyboard shortcuts · tabs/panes · scrollback · performance (GPU-accelerated options like Alacritty or Ghostty).
