Why this course exists. We use computers to automate repetitive work, but rarely automate our own computer use. Most people know a handful of memorised commands and copy-paste the rest. 01What is the shell?

A text interface to your computer: you type a command, it runs programs and shows you their output.

GUIs, voice assistants and LLM interfaces cover most everyday needs, but they only offer what someone built in advance — you can't press a button that doesn't exist. Dropping down to the shell gives you the full power of the tools on your machine.

Terminal

The window

The visual program you open. It displays text and sends your keystrokes to the shell.

Shell

The interpreter

The program inside the terminal that reads your commands, runs programs and returns output. On Linux/macOS this is usually bash.

Opening a terminal

Press Ctrl + Alt + T on most distributions, or search “Terminal” in the app menu. Opens bash by default.

Cmd + Space → type “Terminal” → Enter. Or Applications → Utilities → Terminal.

Win + R → cmd or powershell. These are Windows-specific shells and not what the course uses — install WSL (Windows Subsystem for Linux) or a Linux VM instead.

✅
Check you're in a Unix shell: run echo $SHELL. Output like /bin/bash or /usr/bin/zsh means you're set.

Why bother?

⚡ Speed

Usually much faster than clicking around.

🧩 Composability

Combine small programs to automate almost anything.

🛠 Unavoidable

Open-source installs, CI pipelines and debugging all live here.

Other shells such as zsh and fish add comfort features and share the same core ideas; bash is the focus because it's everywhere.

The machine (hostname) you're logged into.

03Running commands & navigating

The shell splits what you type on spaces: the first word is the program, the rest are its arguments.

bash
missing:~$ date
Fri 10 Jan 2020 11:49:31 AM EST
missing:~$ echo hello
hello

Arguments with spaces

Breaks

cd My Photos
→ two arguments: My and Photos

Quote it

cd "My Photos" or 'My Photos'

Escape it

cd My\ Photos
backslash protects the single space

Getting help

man date

Full manual page for a command — what it does and every option.

date --help

Short built-in help that most commands support.

tldr date

Community cheat-sheet of common examples (install separately). LLMs are good at explaining commands too.

Moving around: cd and pwd

cd (change directory) sets your current working directory; the prompt updates to match. It is a shell builtin, not a separate program — which cd finds nothing. pwd (or echo $PWD) prints where you are.

bash
missing:~$ cd /bin
missing:/bin$ cd /
missing:/$ cd ~
missing:~$
⇥
Press Tab to auto-complete paths and command names. Tools like zoxide (z) learn the folders you visit often.

Absolute vs relative paths

Absolute

Starts with /

The full route from the root of the file system. Works the same wherever you are. e.g. /usr/bin

Relative

Doesn't start with /

Resolved from your current directory. e.g. from /, cd bin takes you to /bin.

Every directory contains two special entries: . = this directory, .. = the parent directory.

🧭 Path resolver — try it
example
missing:~$ cd /
missing:/$ cd bin/../bin/././../bin/..
missing:/$   # each .. undoes a step; each . does nothing

04How the shell finds commands

When you type echo, the shell searches the folders listed in the $PATH environment variable, left to right, and runs the first executable match.

bash
missing:~$ echo $PATH
/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
missing:~$ which echo
/bin/echo
missing:~$ /bin/echo $PATH      # bypass $PATH with a full path
🔎 Watch the $PATH lookup

which prog

Shows which file on disk will run for a name.

ls /bin

List a $PATH folder to see the programs available to you.

05The core toolkit

Small programs that each do one thing well. Filter by job:

cat
Print a file's contents.
cat notes.txt
Nicer: bat (syntax highlighting, paging)
head / tail
First / last few lines of a file.
tail -n 20 app.log
sort
Print lines in sorted order.
sort names.txt
uniq
Drop consecutive duplicate lines — so usually sort first. -c counts.
sort x | uniq -c
ls
List files in a directory; -l for details.
ls -l /
Nicer: eza
grep
Lines matching a pattern (a regular expression). -r searches a whole directory.
grep -r "TODO" .
Faster: ripgrep (rg), recursive by default
find
Recursively find files matching conditions (type, name, age, size).
find ~/Downloads -type f -name "*.zip" -mtime +30
Friendlier: fd
sed
Programmatic editor — most often for find-and-replace.
sed -i 's/old/new/g' file
awk
Parser for column-structured data; pull out fields, filter rows, aggregate.
awk '{print $2}' file awk -F, '{print $2}' data.csv

Anatomy of a sed substitution

sed-i's/pattern/replacement/g'file
-i edit the file in place (otherwise just print the result)
s “substitute” command
pattern a regular expression to match
replacement can refer back to captured groups like \1
g replace every match on a line, not just the first

find recipes

bash
# ZIPs in Downloads older than 30 days
find ~/Downloads -type f -name "*.zip" -mtime +30

# files over 100 MB in home, listed with sizes
find ~ -type f -size +100M -exec ls -lh {} \;

# Python files that contain a TODO
find . -name "*.py" -exec grep -l "TODO" {} \;
💡
In -exec … {} \;, {} is replaced by each matching path, and the ; that ends the command must be escaped as \; so the shell doesn't eat it.

07The bash language

Every command you type is a small program. Bash has variables, conditionals, loops and functions.

Pipes |

Most tools read standard input when no file is given. A pipe connects the standard output of the left program to the standard input of the right one — that's what makes composition possible.

Redirects

SyntaxMeaningExample
> fileSend stdout to a file (overwrite)ls > files.txt
>> fileAppend stdout to a filedate >> log.txt
< fileRead stdin from a filesort < names.txt
2> fileSend stderr (errors) to a filels /nope 2> err.txt
> f 2>&1stdout and stderr to the same filemake > build.log 2>&1
| tee fSave a copy to a file and pass it oncmd | tee full.log | grep CRITICAL
0

stdin

Input — your keystrokes by default.

1

stdout

Normal output to the terminal.

2

stderr

Error messages, kept separate.

Conditionals

bash
if [ -f notes.txt ]; then
  echo "found it"
else
  echo "missing"
fi

The condition is just a command: it “succeeds” if it exits with status 0. Most often it's test, written as [ … ] — e.g. [ -f file ] (file exists) or [ "$var" = "text" ]. In bash, prefer [[ … ]], a builtin with fewer quoting surprises.

$?

Exit status of the last command (0 = success).

a && b

Run b only if a succeeded.

a || b

Run b only if a failed.

Loops & command substitution

bash
# repeat while a command keeps succeeding
while ping -c1 host >/dev/null; do sleep 5; done

# iterate over a list
for f in a b c d; do echo "$f"; done

# $( ) runs a command and splices in its output
for i in $(seq 1 10); do echo "run $i"; done
⚠️
Old scripts use backticks `seq 1 10`. Prefer $( ) — it can be nested.

08Writing scripts

Once a command grows, put it in a .sh file. This one reruns a test until it fails while the CPU is under load — handy for flaky tests.

flaky.sh
#!/bin/bash
set -euo pipefail

# Start CPU stress in background
stress --cpu 8 &
STRESS_PID=$!

# Setup log file
LOGFILE="test_runs_$(date +%s).log"
echo "Logging to $LOGFILE"

# Run tests until one fails
RUN=1
while cargo test my_test > "$LOGFILE" 2>&1; do
    echo "Run $RUN passed"
    ((RUN++))
done

# Cleanup and report
kill $STRESS_PID
echo "Test failed on run $RUN"
echo "Last 20 lines of output:"
tail -n 20 "$LOGFILE"
echo "Full log: $LOGFILE"

&

Run a command in the background so the script continues.

$!

PID of the last background job — used later to kill it.

((RUN++))

Arithmetic expansion: integer maths inside bash.

The shebang #!

If an executable file starts with #!/path/to/program, running it launches that program and hands it the file. So #!/bin/bash runs the script in bash — and #!/usr/bin/python3 works for Python scripts too. You also need execute permission: chmod +x flaky.sh, then ./flaky.sh.

Strict mode: set -euo pipefail — click each flag

-e
exit on error
If any command fails, the script stops right there instead of ploughing on.
-u
no undefined vars
Using a variable that was never set crashes the script, instead of silently becoming an empty string.
-o pipefail
pipes can fail
If any program inside a | chain fails, the whole pipeline counts as failed.
🪤
Bash is full of gotchas. Run your scripts through shellcheck. Once a script passes ~100 lines, consider rewriting it in a “real” language like Python — LLMs are good at that translation.
